# 公共数据模型策略

当前产品定位是单人个人收藏站，公共数据继续采用 `document-kv-v1`，不在没有规模信号前引入卡片级 CRUD。`public_data` 仍由站点设置、标签和卡片组成，SQLite 与 Redis 保持统一文档契约。

## 监控指标

管理员可以读取 `/api/storage/data-metrics` 查看当前文档的标签数、卡片数、JSON 字节数和上限利用率。SQLite 额外返回数据库页、空闲页、媒体表和旧媒体统计。接口需要管理员 Session。

当前触发线：

- 卡片数达到 1600（上限 2000 的 80%）
- 标签数达到 160（上限 200 的 80%）
- JSON 大小达到 800 KiB（请求上限 1 MiB 的 80%）
- 出现多人同时编辑或需要跨实例写入

达到任一条件后，下一阶段改为卡片、标签、设置分离的 Repository，并通过离线迁移脚本生成新版本数据。迁移前必须保留旧文档只读回退路径和备份。

SQLite 公共数据保存已经在单进程内使用事务完成版本检查和写入；Redis 使用 Lua 脚本完成原子版本检查。两者仍不提供跨不同数据中心的分布式事务。
